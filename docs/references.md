# References

Use these primary sources for standards and implementation details. Recheck the source before applying requirements because guidance and product behavior can change.

## Standards and public-sector guidance

- [NIST SP 800-63-4: Digital Identity Guidelines](https://csrc.nist.gov/pubs/sp/800/63/4/final) — identity proofing, authentication, and federation.
- [NIST SP 800-63C-4: Federation and Assertions](https://csrc.nist.gov/pubs/sp/800/63c/4/final) — federation-specific guidance.
- [CISA: Identity and Access Management Recommended Best Practices for Administrators](https://www.cisa.gov/sites/default/files/2023-12/ESF%20IDENTITY%20AND%20ACCESS%20MANAGEMENT%20RECOMMENDED%20BEST%20PRACTICES%20FOR%20ADMINISTRATORS%20PP-23-0248_508C.pdf) — enterprise IAM practices, including MFA and privileged access.

## Provider documentation

- [AWS IAM security best practices](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html) — federation, temporary credentials, MFA, least privilege, and access analysis.
- [Microsoft Entra ID Governance overview](https://learn.microsoft.com/en-us/entra/id-governance/identity-governance-overview) — lifecycle workflows, entitlement management, and access reviews.
- [Microsoft privileged access architecture](https://learn.microsoft.com/en-us/security/zero-trust/adopt/implement-privileged-access) — privileged identities, trusted devices, elevation, and monitoring.

These links are starting points, not a compliance determination. Map requirements to your organization’s scope, risks, and applicable obligations.
